# 提交前复查：2026-09-07

本轮接着 [9 月 5 日的复查与性能测量](performance-review.md)，修复后再次交叉检查，
并对最终代码重新验证。此前的性能数据保留其原始日期、二进制摘要和比较基线。

## 本轮修复

- **离开时间与缺口**：长时间未采样，中途输入后又离开时，只把无法确认的中间窗口列为缺口，
  不再把末尾已确认的离开时间也算进去。覆盖采样、切窗、锁屏、睡眠和退出，并测试系统时钟回拨。
- **输入时间倒退**：系统返回更早的最后输入时间时，保留当前活动段已经见证的较新输入，
  避免少记有效时长；没有输入的新证据就不延长离开截止时间。新增回归用例在修复前将 390 秒少计为
  300 秒，修复后通过。Windows 的该时间戳确实不保证递增，参见
  [GetLastInputInfo 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)。
- **重启持久化屏障**：完整字典条目或 DPAPI 密钥可见，不代表上一进程已经同步到磁盘。
  writer 启动时同步已有密钥和字典，再允许确认后续记录；同步失败则停止并保留原数据。
  故障测试在已打开句柄处注入真实 Windows 同步失败，验证没有成功 ACK，也没有写入引用记录。
- **历史文件扫描一致性**：统一识别大小写不同的 `.LOG` 与 `.PART-xxxxxx.LOG`，
  避免漏查已有编号、误建新密钥或复用分片编号。同号文件歧义明确报错。
  链接或目录联接等 reparse 数据目录、日志在启动核验时明确拒绝，避免静默漏扫。
- **退出与服务启动**：保留初始化期间收到的停止请求；托盘线程即使收到了退出消息，清理等待也有上限。
  先启动最终持久化，再做托盘清理。退出时额外核对前台状态，身份不符的未确认尾部成为缺口。
  服务停止失败报告非零退出状态，命名事件的权限错误不再冒充“没有运行”。
- **查询与导出**：状态探测只打开已有单实例对象，避免查询阻止同时启动；权限或目录结构错误明确显示。
  报表总数与百分比使用完整结果，之后才应用 `--top`。实时 tail 在日志块尚未写完时提示并重试，
  恢复后避免重复输出；`--once` 保持报错行为。CSV 补齐独立回车的转义。

## 可靠性边界

启动核验仍会遍历全部历史，所需时间随历史数据增长。已有密钥与字典现在必须可写，以完成启动同步。
不支持的数据链接布局会明确报错；可以使用普通目录中的完整数据副本。
历史日志按块扫描，采集和写入队列有上限；字典索引仍随历史唯一字符串数量增长，整个进程并非固定内存。

退出保护覆盖已经进入本进程的采集工作，最终快照也可发现前台身份不一致；
无法证明 Windows 尚未派发的全部回调已经清空。例如完全未派发的 A→B→A 切换，单次快照无法还原。
没有通过放宽认证、凭空补活动或无限等待来掩盖这一限制。

v1 仍无法检测恰好截在完整认证块边界的日志尾部丢失，也无法恢复尚未持久化的数据。
旧版读取程序不理解本次新增的缺口扣除语义，查看本次记录应使用新版程序。
测试没有实际触发系统睡眠、注销、关机，也没有安装服务或改动用户自启动。

### 真实桌面资源

默认设置和开启标题各做两轮：同一桌面并行运行两版，预热 5 秒，再采样 64 秒。
没有编译或压力回放并行运行，没有输入注入、切换焦点、安装或工作集修剪。
每组都有前台窗口与 Shell，实际写入应用字典；自然输入间隔为 0–19.969 秒，没有进入 5 分钟 AFK。
8 次 daemon 运行全部退出码 0，正常停止、无强制终止、无 stderr 错误。

内存中位数略低，**没有整体 CPU 改善**。开启标题时两轮配对 cycles 增加约 **5.3% 和 7.3%**，
CPU 时间也更高，最终构建约占单个逻辑核的 **0.61%–0.78%**。这些短时自然桌面样本不用于归因单个修改，
也不把不同日期的桌面活动当作相同负载比较。默认配置的零 CPU 时间读数处于计量分辨率附近，不能理解为零工作。
工作集含共享驻留页面；私有提交不是私有驻留。I/O 是进程请求量，不是物理磁盘流量。
