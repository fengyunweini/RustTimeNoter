# 空闲输入反证复审：2026-09-08

本轮基于 PR #10 的 `bf41688`，修复合并前审查指出的 P2。
此前 183 项测试及会话失效回放没有覆盖“新读到的输入时间早于旧空闲观察”的反证，不能据此排除这个问题。

## 复现与修复

AFK 阈值为 300 秒：A@0/input0，A@600/input0，A@1200/input540。
旧版只记录 A 0–300 秒，缺口为空。输入 540 明确反证了后面的空闲判断，却因它早于上次观察 600 被忽略。
三项新的单元回归和真实 writer/query 跨层回归先在旧生产逻辑上失败，确认不是仅由新增断言推断的问题。

修复在更新已见输入之前检查旧证据：

- 新输入已发生于旧空闲观察之前或同刻：那次观察不再可信，从旧 AFK 截止点补缺口。
  原例现在保留 **A 0–300 秒**，补 **Gap 300–840 秒**，840 之后仍为空闲。
- 输入发生在旧空闲观察之后：沿用此前可信观察到新截止点的缺口，不回溯抹去更早的已知空闲。
- 已经进入锁屏/休眠后，才见到发生在抑制开始之前的新输入：仍使用会话保留的旧输入证据，
  但把缺口截在锁屏/休眠起点，保留其后已知排除区间。
- 起点不早于本次捕获的首次时间锚点；相同/回退输入不反复修正，未来输入不作为证据。

修复集中在 `correct_input_discontinuity`，覆盖采样、前台事件和直接 finish，均在 `observe_input` 改写旧证据前执行。
已经在正常活动中的连续输入沿原来的早退路径处理。迟到事件已有相应的反证处理，本轮未重写该路径。
缺口不归属任何应用；前台事件在等待恢复时仍需采样确认，新的活动只从确认时刻开始。

例如 AFK 5 秒，A@0/input0、Lock@10，直到 locked Sample@20 才读到 input4：现在补 Gap 5–9，
9–10 的新空闲后缀和 10 之后的锁定均保留。直接 finish 和休眠对应入口也有回归。

## 验证与边界

Debug、Release 各 **189 项测试通过**（177 库、1 程序、5 数据完整性、6 隔离端到端），新增五项单元测试及一项跨层测试。
Clippy `-D warnings`、变更文件格式、diff 空白检查和发布版构建通过。

跨层测试先把 A 0–300 秒写入真实加密日志并 ACK，再提交 input540 的修正：查询保留 300 秒活动，
报告明确显示缺口，缺口合计 540 秒，没有把不确定时间算给 A。
单元测试覆盖输入在旧截止点/旧观察之前、同刻和之后，以及恢复活动、直接关闭、锁屏、休眠、会话起点和时钟变化。

两路独立检查分别完成 81 组边界断言回放、11 条边界断言回放，并重跑原场景与相邻入口的九种诊断回放。
修复后的交叉复查未再发现新的可复现阻断项。
这些仍是逻辑与隔离存储验证；没有做真实 Windows 输入时间回退、关机、休眠或服务生命周期实测。
跨多次历史状态变化的任意久远事件，仍受已有固定历史信息边界限制。
